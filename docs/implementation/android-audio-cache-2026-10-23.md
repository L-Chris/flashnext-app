# 原生 Android 音频复用、磁盘缓存与预加载

## 播放器与生命周期

`AudioController` 在前台学习期间按需创建一个 ExoPlayer，并在翻面、切卡、手动停止和播放结束后保留实例。停止时先使本轮播放标识失效、移除监听器，再停止和清空播放列表；异步准备和监听事件均核对标识，防止旧卡片改变新卡片状态。

进入后台、离开学习、切换服务器时释放播放器并取消预加载；回到前台不会自动恢复被中断的声音。ViewModel 清理时关闭控制器协程。媒体音量、正反面排序、焦点丢失和耳机断开后的停止规则保留。同期的播放图标和评分按钮调整见 [UI 对齐记录](android-ui-parity-2026-10-22.md)。

## 缓存与版本

进程共享一个 `AudioStore`，通过 Media3 `SimpleCache`、LRU 淘汰和 `CacheDataSource` 读写 `cacheDir/study-audio-v1`。音频数据上限为 128 MiB，不计入 APK 下载体积；系统可以清理缓存，不保证离线保留。缓存初始化与文件操作在 IO 线程执行，播放和预加载共用 OkHttp 连接池。缓存初始化、索引写入不可用时回退网络；读取或解析缓存异常时移除对应资源，绕过缓存联网重试一次，失败后交由用户重试。

缓存键包含规范化完整 URL（含服务器及查询参数）和内容版本的摘要。优先读取音频 `sha256`，兼容已有 `playback.sha256`；缺少哈希时，带 `playback` 版本参数的地址可以跨启动复用，普通地址以当前学习会话隔离。哈希用来标识内容版本，并非播放器逐段执行的完整性校验。新音频在下一次队列刷新获得新元数据后生效。

后端 `mediaView` 新增可选的顶层 `sha256`，对应实际返回的原文件或响度校正版；原来的 `mediaId`、`bytes`、URL 和 `playback` 均保留，无需数据库迁移。App 解析可选字段，因此兼容未更新后端。

## 预加载

队列取得后即可准备数据，不等待文字或公式字体渲染，但自动出声仍等待当前卡片内容就绪。仅在当前卡开启自动播放时预加载：当前面、另一面、下一张开启自动播放的卡片正面，按界面顺序排序并按缓存键去重。

- 单文件已知大小为 1 字节至 1 MiB 才预取；大文件和大小未知的文件按需播放。
- 每批计划总大小最多 2 MiB，同时最多一个预加载任务访问缓存和网络。
- 已完整缓存的内容跳过；关闭自动播放时不做推测性下载，实际播放仍写入缓存。
- 实际播放取消预加载的 HTTP 请求，并异步等待写入锁释放后准备播放器，不在主线程等待文件下载。
- 翻面和队列切换更新优先级，评分或撤销请求期间暂停预加载；进入后台、退出学习和切换服务器均取消。
- 连接超时 8 秒、读取超时 15 秒、单请求期限 30 秒；预加载失败不显示学习错误，也不无限自动重试。

完整预取后补充文件长度元数据，避免播放器探测文件末尾时对已经完整缓存的音频再发网络请求。播放时再次确认完整缓存的已知长度，覆盖预取刚完成便被播放抢占的情况。

## 验证

```sh
android/gradlew -p android testDebugUnitTest lintDebug assembleRelease
adb shell am instrument -w \
  -e class com.rethinkos.flashnext_app.AudioPlaybackTest \
  com.rethinkos.flashnext_app.native.test/androidx.test.runner.AndroidJUnitRunner
```

JVM 覆盖服务器、哈希、版本参数和旧后端会话隔离、字段兼容、预加载排序和预算，以及队列就绪、翻面、后台、退出时的预加载回调。设备用例全部使用独立缓存目录和本机模拟音频服务，不修改生产学习记录。

本轮验证结果：

- 33 项 JVM 用例通过，Android Lint 与三个架构的 release 构建通过，固定安装签名保持一致。
- v0.3.4 发布前，Android 15 模拟器一次运行 12 项用例通过：10 项音频用例覆盖顺序播放、焦点中断、完整缓存离线重播、关闭并重建缓存后的复用、播放器复用、预加载命中与哈希变更、慢预加载抢占和后台停止、旧加载请求快速替换、缓存目录异常回退、损坏缓存单次恢复和重试上限、LRU 容量控制；另 2 项界面用例验证复习流程及小屏大字体布局。
- 后端 TypeScript 类型检查和 3 项媒体接口集成用例通过，覆盖选中音频哈希、原始/处理版字节、Range、HEAD、ETag 和关联删除保护。测试使用 Node.js 24.16.0 的临时 SQLite 数据库。
- 本地 arm64 release APK 为 2,403,724 字节，较已发布 v0.3.3 的 2,370,956 字节增加 32 KiB，约 1.38%；音频缓存占用属于安装后数据。
- 本轮未做真机蓝牙路由和主观响度对比，也未向生产服务写入学习记录或部署后端。

Debug 的 `StudyAudio` 日志保留音量诊断，并记录从播放请求开始到首次进入播放状态的 `readyMs`，包含缓存初始化和预加载让出时间；不把模拟器耗时作为真机性能保证。
